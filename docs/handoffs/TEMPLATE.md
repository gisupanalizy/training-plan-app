# Handoff — Txx — krótki opis

- Data i autor:
- Zadanie / status po sesji:
- Branch / commit / stan zmian (lub brak Git):
- Powiązany wcześniejszy handoff:

## Cel i wykonana praca

Co faktycznie zrobiono i które kryteria spełniono. Odróżnij implementację, dokumentację i propozycje.

## Zmienione pliki

Linki i krótkie uzasadnienie zmian. Wskaż migracje i zmiany kontraktów.

## Weryfikacja

Dokładne polecenia lub kroki manualne, wynik i środowisko. Wskaż mocki, prawdziwe API, niewykonane sprawdzenia i powód. Nie wklejaj sekretów ani prywatnych danych.

## Decyzje i zmiany planu

ID decyzji, zmienione zadania/zależności, powód i wpływ. Wymień zaktualizowane dokumenty.

## Pozostała praca i blokery

Konkretne problemy, ryzyko, wymagane dane/dostępy; co można robić niezależnie.

## Następny krok

Jedno wskazane zadanie, pierwszy krok i pliki do przeczytania. Jeśli zadanie nieukończone, wyjaśnij dokładnie, jak je kontynuować.

## Stan środowiska

Procesy/serwery, zasoby tymczasowe, niewysłane zmiany; tylko nazwy wymaganych zmiennych, nigdy wartości. Jeśli nic nie uruchomiono, napisz to jawnie.

## Prompt dla kolejnego agenta

Rekomendowany model i poziom rozumowania oraz krótkie uzasadnienie kosztowe:

Wklej gotowy prompt zgodny z WORKFLOW, identyczny z przekazanym w odpowiedzi końcowej. Wskaż konkretne zadanie, handoff, pliki startowe, zakres, sprawdzenia i blokery. Nie pozostawiaj placeholderów w ukończonym handoffie. Jeśli zakres jest zakończony, napisz, że nie ma kolejnego zadania.
